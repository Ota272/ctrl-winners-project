# CapFinance Game 

Веб-приложение — **игровой финансовый тренажёр**: виртуальный портфель, торговля разными классами активов, обмен валют, депозит, рулетка, рейтинг игроков и встроенный ИИ-ассистент («Капитал Бот») на базе Google Gemini. Интерфейс ориентирован на мобильный вид (одностраничная игра с переключением экранов), тексты в основном на русском языке.
(разрабатывался в рамках республиканского хакатона)

## Возможности

- **Регистрация и вход** — учётные записи в SQLite; после регистрации выдаётся стартовый капитал **100 000 USD** (виртуально).
- **Портфель** — наличные USD, валюты **KZT** и **JPY**, банковский **депозит**, коллекция активов в JSON.
- **Классы активов** (логика и цены в клиентском `static/game.js`):
  - **Акции** — котировки через [Finnhub](https://finnhub.io/) (реальные цены, где доступно).
  - **Криптовалюты и «металлы»** — цены через публичный API [CoinGecko](https://www.coingecko.com/) (`simple/price`).
  - **Скины CS2 и подарки (Telegram-style gifts)** — симулированные каталоги с вариациями; часть цен привязана к курсу **TON** из CoinGecko.
  - **Депозит** — отдельный баланс для «безопасного» хранения в рамках игры.
- **Обмен валют** — фиксированные курсы в коде (например USD/KZT, USD/JPY).
- **Рулетка** — азартная мини-игра с фиксированной стоимостью вращения и возможным крупным выигрышем; операции пишутся в историю с типом `GAME`.
- **Аналитика** — графики (Chart.js), история операций, учёт убытков по рулетке для отображения.
- **Рейтинг** — топ-10 игроков по сумме `usd + deposit`.
- **ИИ-чат** — маршрут `/api/chat`: контекст портфеля + системный промпт «брокера»; требуется `GEMINI_API_KEY`.
- **Статические страницы** — магазин (витрина), правила, оферта, политика, отчёт (шаблоны в `templates/`).

## Быстрый старт

1. Клонируйте репозиторий и перейдите в каталог проекта.

2. Создайте виртуальное окружение и установите зависимости:

   ```bash
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```

3. Инициализируйте базу данных:

   ```bash
   python create_db.py
   ```

4. Задайте переменные окружения (минимум `SECRET_KEY`; для чата — `GEMINI_API_KEY`). См. [Переменные окружения](#переменные-окружения).

5. Запустите сервер разработки:

   ```bash
   python app.py
   ```

   По умолчанию приложение слушает **порт 5000** (или значение переменной `PORT`). Откройте в браузере `http://127.0.0.1:5000/` — при отсутствии сессии произойдёт редирект на `/login`.

## Переменные окружения

| Переменная | Назначение |
|------------|------------|
| `SECRET_KEY` | Секрет Flask для подписи сессий. В коде есть запасное значение только для локальной разработки — **в production обязательно задайте свой надёжный ключ**. |
| `GEMINI_API_KEY` | Ключ Google AI Studio / Gemini для маршрута `/api/chat`. Если не задан, модель не инициализируется, ответы чата будут недоступны или с ошибкой. |
| `PORT` | Порт HTTP-сервера (используется в блоке `if __name__ == "__main__"`). |

Ключ **Finnhub** сейчас задаётся в `static/game.js` (`STOCK_API_KEY`). Для продакшена лучше вынести его на бэкенд или в переменные окружения и подставлять при сборке/через отдельный конфиг, чтобы не светить ключ в репозитории.

## База данных

Скрипт `create_db.py` создаёт три таблицы:

1. **`users`** — `id`, `username` (уникальный), `password` (в текущей реализации хранится **в открытом виде** — см. раздел про безопасность).
2. **`user_state`** — состояние игры: `user_id`, `balance`, `deposit`, `usd`, `kzt`, `jpy`, `assets` (JSON-строка с владением активами).
3. **`history`** — журнал операций: тип (`BUY`, `SELL`, `EXCHANGE`, `GAME` и т.д.), актив, количество, цена, сумма, снимок баланса для графиков, время.

Путь к файлу БД в `app.py`:

- если на сервере существует каталог **`/data`** (типичный паттерн для [Amvera](https://amvera.ru/) и подобных платформ), используется **`/data/database.db`**;
- иначе — **`database.db`** в корне проекта (локальная разработка на Windows/macOS/Linux).

## HTTP API

Все JSON API, кроме отдельно оговорённых, ожидают сессионную авторизацию (cookie после успешного `/api/login`).

| Метод и путь | Описание |
|--------------|----------|
| `POST /api/register` | JSON: `username`, `password`. Создаёт пользователя и начальное `user_state` с **100 000 USD**. |
| `POST /api/login` | JSON: `username`, `password`. Устанавливает сессию. |
| `GET /logout` | Очищает сессию, редирект на логин. |
| `GET /api/get_state` | Текущее состояние портфеля + поле `roulette_loss` (для UI). |
| `POST /api/save_game` | JSON: `usd`, `kzt`, `jpy`, `deposit`, `assets` — сохранение прогресса с клиента. |
| `GET /api/history` | До 50 последних записей истории пользователя. |
| `POST /api/log_action` | Логирование одной операции (покупка, продажа, игра и т.д.) в `history`. |
| `GET /api/leaderboard` | Топ-10: `username`, `capital` (= usd + deposit). |
| `POST /api/chat` | JSON: `message`, `context` (например `usd`, `assets`). Ответ: `reply` от Gemini. |

Страницы: `/`, `/login`, `/register`, `/shop.html`, `/rules.html`, `/offer.html`, `/policy.html`, `/report.html` — рендер шаблонов из `templates/`.

## Внешние сервисы и ключи

- **CoinGecko** — публичный endpoint без ключа в типичном сценарии; возможны лимиты по частоте запросов.
- **Finnhub** — для котировок акций нужен API-токен; запросы идут из браузера (`game.js`).
- **Google Gemini** — серверный ключ в `GEMINI_API_KEY` для `/api/chat`.

## Запуск в production

Пример с Gunicorn (из корня проекта, после `pip install -r requirements.txt`):

```bash
gunicorn -w 4 -b 0.0.0.0:8000 app:app
```

Проксируйте HTTPS через nginx или облачный балансировщик; задайте `SECRET_KEY` и при необходимости `GEMINI_API_KEY` в окружении процесса.

## Деплой (в т.ч. Amvera)

- Приложение уже учитывает постоянное хранилище через **`/data/database.db`**, если каталог `/data` смонтирован на платформе.
- Переменные окружения настраиваются в панели провайдера.
- Для веб-процесса обычно указывают команду вида `gunicorn app:app` и порт из переменной окружения хостинга.

## Известные ограничения и безопасность

1. **Пароли** хранятся в БД без хеширования — это допустимо только для учебного/демо-проекта. Для реальных пользователей нужны **хеши** (например bcrypt/argon2) и политика сложности паролей.
2. **Секреты в репозитории** — API-ключи в JS или в вспомогательных скриптах не должны попадать в публичный git. Используйте `.env`, секреты CI/CD и ротацию ключей.
3. **Дублирование кода** — в `app.py` встречаются повторные фрагменты (например функция `db()` и импорты); при развитии проекта имеет смысл почистить файл и добавить линтер/форматтер.
4. **CORS и rate limiting** — при отдельном фронтенд-домене понадобится настройка CORS; для публичного API — ограничение частоты запросов.
